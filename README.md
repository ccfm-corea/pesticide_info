# 가농인증 허용 농약 조회 및 방제력 작성

가톨릭농민회 과수위원회 · 가농인증 생산자용 웹앱

주소 하나만 열면 바로 씁니다. 로그인도 설치도 없습니다.

- 대상 작물: 사과, 배, 복숭아, 자두, 단감 (생산규정상 가농인증 품목 5종)
- 생산자가 적은 내용은 그 사람 휴대전화에만 남습니다. 어디로도 보내지 않습니다.

# 자료 갱신하는 법

**일 년에 한두 번, 새 농약 목록이 나왔을 때만 하면 됩니다.**
GitHub은 만질 일이 없습니다. **구글 시트 하나만** 만지면 됩니다.

## 1. 농약 목록 내려받기

농약안전정보시스템(psis.rda.go.kr) → 농약제품목록 → 엑셀 내려받기

## 2. 시트에 넣기

조직 드라이브의 **「가농인증 허용 농약 데이터(계속 업데이트)」** 시트를 엽니다.

1. **파일 → 가져오기 → 업로드** → 내려받은 엑셀 선택
2. 가져오기 위치에서 **「스프레드시트 바꾸기」** 를 고릅니다
3. **데이터 가져오기**

> 탭을 나누거나 수식을 넣을 필요가 없습니다. 통째로 갈아엎어도 괜찮습니다.
> 앱이 구글에 "5개 작물의 살균·살충 약제만 달라"고 요청해서 받아 가기 때문입니다.

## 3. 기준일 적기

**A1 칸**의 「농약제품목록」이라는 글자를 지우고, 그 자리에 자료 날짜를 적습니다.

```
A1  2026-07-27
```

이 날짜가 앱 화면 위에 그대로 뜹니다. 안 적으면 앱이 받아 온 날짜로 대신 표시합니다.

## 4. 확인

앱 주소를 열어 위쪽 **자료 기준일**이 바뀌었는지 봅니다.
구글이 최대 5분쯤 늦게 반영할 때가 있습니다.

# 처음 한 번만 하는 준비

## 시트 공유

시트 → **공유** → 「일반 액세스」를 **링크가 있는 모든 사용자 · 뷰어** 로 둡니다.
앱이 읽으려면 이 설정이 필요합니다. 농약 등록정보는 공개 자료이므로 문제가 없습니다.

## 앱에 주소 넣기

`index.html` 위쪽의 이 줄에 시트 주소를 넣습니다. **처음 한 번뿐입니다.**

```javascript
const SHEET_URL = "https://docs.google.com/spreadsheets/d/…/edit?usp=sharing";
```

시트 주소를 그대로 넣으면 됩니다. 주소 뒤에 `gid=` 가 붙어 있으면 지우십시오.
탭이 바뀌어도 첫 번째 탭을 읽도록 하기 위해서입니다.

> **혹시 자료를 못 받아 온다면** 구글이 브라우저의 직접 읽기를 막는 경우입니다.
> 그때는 시트에서 **파일 → 공유 → 웹에 게시 → 쉼표로 구분된 값(.csv) → 게시** 를 하고,
> 나온 주소를 `SHEET_URL` 에 대신 넣으면 됩니다. 앱이 두 방식을 모두 알아봅니다.

# 넘겨줄 때

- **시트** — 조직 드라이브에 두고 편집 권한을 후임에게 넘깁니다. 이 문서 위쪽 네 단계만 알려주면 됩니다
- **앱** — GitHub Organization 저장소에 두고 **소유자를 두 명 이상** 둡니다.
  개인 계정에 두면 그 사람이 떠날 때 아무도 손댈 수 없습니다
- **이 문서** — 저장소 첫 화면에 뜨므로 따로 챙길 필요가 없습니다

갱신을 몇 년 안 해도 앱은 멈추지 않습니다. 마지막 자료로 계속 돌아가고,
화면의 기준일만 오래된 날짜로 남습니다.

# 앱이 하는 일

| 생산규정 | 앱 처리 |
|---|---|
| 제초제 금지 | 용도 살균·살충·균충만 보여줌 |
| 호르몬제 금지 | 생장조정제 제외 |
| 맹독성·고독성 금지 | 인축독성 Ⅰ·Ⅱ급 선택 불가 |
| 잔류기간 ×2 | `라벨 14일 → 가농 28일` 병기 + 마지막 살포일 계산 |
| 항생제 금지 | 위원회 결정에 따라 별도 판정하지 않습니다 |

맹독성·고독성·발암성 농약은 등록 단계에서 걸러져 원자료에 들어오지 않습니다.
2026-07-27 기준으로 국내 등록 농약에 맹독성은 하나도 없고,
고독성은 144,073건 중 103건이며 **과수 5종에는 하나도 없습니다.**

잔류기간 ×2 계산은 `수확 예정일 − (안전사용기준 × 2)` 입니다.
수확 예정시기는 달 + 상순·중순·하순으로 받고 각각 1일·11일·21일을 기준으로 삼습니다.
해석이 위원회에서 달리 정해지면 `index.html` 의 `lastSpray()` 한 곳만 고치면 됩니다.

# 파일

```
index.html      앱 전체 (이 한 파일이 전부입니다)
README.md       이 문서 — 자료 갱신하는 법
관리자문서.md    앱을 고치거나 점검할 때 보는 문서
```

앱을 직접 손봐야 할 일이 생기면 **`관리자문서.md`** 를 보십시오.
자료가 어떻게 걸러지는지, 어디를 고쳐야 하는지, 고친 뒤 무엇을 확인해야 하는지 적혀 있습니다.

앱은 받아 온 자료를 휴대전화에 저장해 둡니다. 과수원처럼 통신이 약한 곳에서도 열립니다.
새로 받은 자료가 이전보다 절반 이하로 줄면 잘못된 것으로 보고 저장해 둔 자료를 계속 씁니다.
